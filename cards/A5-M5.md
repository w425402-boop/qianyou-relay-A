## 1. 你这一棒交付什么

**为什么拆给你**：考察多字段表单逐项校验、30 秒自动草稿持久化，以及与发现页列表的跨模块契约联动。

逐条交付，不许减项：

1. 发起表单 **7 个字段**：标题、分类（下拉 6 类必选）、时间、地点、费用、人数上限、描述。
2. **提交校验**（不过就标红该字段并提示）：标题必填 2–20 字；分类必选；时间必填且晚于现在（否则提示"时间须晚于现在"）；地点必填；费用数字 ≥ 0；人数上限整数 2–50；描述选填 ≤ 200 字。
3. **草稿**：填表过程**每 30 秒自动保存一次**＋"保存草稿"手动按钮，存 `store.draft`；刷新后提示"恢复上次草稿？"，点确认恢复。
4. **发布**：新活动 `id` 为 `a`＋时间戳，`status` 为 `ongoing`，`joined` 为 0，`hostId` 为 `u01`；发布后跳新活动详情页（`#/detail/:id`），回到发现页列表条数＋1。

**交付物**：`js/modules/publish.js`；`tests/check.js` 里追加 2 条断言（校验函数对非法返回假、对合法返回真）；《交接单》。

## 2. 契约前置（先看契约再写代码，10 分钟）

对照 CONTRACT.md 第 4 节，本棒 2 个对外函数：

| 函数 | 入参 | 返回值 | 出错行为 |
| :--- | :--- | :--- | :--- |
| `QY.renderPublish()` | 无 | 渲染 7 字段表单＋草稿按钮，返回 `undefined` | 容器不存在 → 静默返回 |
| `QY.validatePublish(fields)` | `Object`（7 字段原始值，多为字符串） | `boolean`：全合法 `true`，任一不合法 `false` | 入参缺失 → `false`，不抛；**不许返回错误对象**（check.js 按布尔断言） |

展示的错误文案单独走 `QY.validatePublishDetailed(fields)`（可选，自己加）：返回 `{ valid, errors: { field: msg } }`，供标红定位到字段。契约函数只负责布尔。

草稿结构写进 `store.draft`：
```js
// 落库时的形状
state.draft = { title, category, time, place, cost, capacity, desc, savedAt: '2026-11-25T10:00:00.000Z' };
```

**只许改（owns）**：`js/modules/publish.js`
**只许追加（appendOnly）**：`css/style.css`（只追加 M5 区块）、`tests/check.js`（只追加 M5 断言）
**不属于你**：`js/router.js`（M1 owns）、`js/modules/discover.js`（M2 owns）—— 列表条数＋1 靠 M2 重渲染，你只负责把新活动写进 store 后跳 `#/detail/:id`

红线：**不遵守就是契约违规，扣 3 分/条。**

## 3. 定桩说明（本棒要摘掉的桩）

开局两个函数是 `QY.seam.stub('M5 QY.validatePublish')` 形态，一调用即抛 `[SEAM 未实现]`。

**交付标准**：M5 的 2 个契约函数全部不再是桩，`node tests/contract.js` 的「本棒模块仍是桩」检查转绿。

```js
// js/modules/publish.js —— 从桩到真实现
(function (root) {
  var QY = (root.QY = root.QY || {});
  var CATS = ['美食', '咖啡', '桌游', '运动', '文娱', '户外'];
  var ME = 'u01';

  // 逐字段校验，返回 { valid, errors }；契约函数包一层布尔
  QY.validatePublishDetailed = function (f) {
    var v = f || {}, errors = {};
    var title = String(v.title == null ? '' : v.title).trim();
    if (title.length < 2 || title.length > 20) errors.title = '标题须为 2–20 字';
    if (CATS.indexOf(v.category) === -1) errors.category = '请选择分类';
    var t = new Date(v.time).getTime();
    if (!v.time || isNaN(t)) errors.time = '请选择时间';
    else if (t <= Date.now()) errors.time = '时间须晚于现在';        // 文案固定，验收清单逐字核对
    if (!String(v.place == null ? '' : v.place).trim()) errors.place = '地点必填';
    var cost = Number(v.cost);
    if (v.cost === '' || isNaN(cost) || cost < 0) errors.cost = '费用须为 ≥0 的数字';
    var cap = Number(v.capacity);
    if (!(Math.floor(cap) === cap && cap >= 2 && cap <= 50)) errors.capacity = '人数上限须为 2–50 的整数';
    if (String(v.desc == null ? '' : v.desc).length > 200) errors.desc = '描述不超过 200 字';
    return { valid: Object.keys(errors).length === 0, errors: errors };
  };

  // 契约函数：布尔，供 check.js 直接断言
  QY.validatePublish = function (fields) { return QY.validatePublishDetailed(fields).valid; };

  // 发布：id = 'a' + 时间戳，joined=0，hostId=u01，写回整份 state 后跳详情
  QY.publishActivity = function (fields) {
    if (!QY.validatePublish(fields)) return null;
    var state = QY.store.load();
    var id = 'a' + Date.now();
    state.activities.push({
      id: id, title: fields.title.trim(), category: fields.category,
      desc: fields.desc || '', time: new Date(fields.time).toISOString(),
      place: fields.place.trim(), cost: Number(fields.cost), capacity: Number(fields.capacity),
      joined: 0, signedUserIds: [], hostId: ME, status: 'ongoing',
      distance: 0, tags: [fields.category]
    });
    state.draft = null;                    // 发布成功即清草稿，否则下次误恢复
    QY.store.save(state);
    location.hash = '#/detail/' + id;      // 详情页由 M4 渲染，你只跳
    return id;
  };
})(typeof window !== 'undefined' ? window : globalThis);
```

两个坑：①`capacity` 一定是数字型，写成字符串会让 M4 的"已满员"判断静默失效；②自动草稿的 30 秒定时器要在离开页面时清掉，否则跳详情后还在往 `store.draft` 里写。

## 5. 自测闸门（不过不许提 PR）

**闸门一 功能**：`node tests/check.js` 输出全 PASS（别人的桩 SKIP 不算失败，M5 的断言必须 PASS 不能 SKIP）。Q5 验收清单逐条自检：

☐ 人数填 51 被拦；费用填 -5 被拦

**闸门二 契约**：`node tests/contract.js` 零违规 —— 越界（碰 M1/M2/M4 文件都算）、缺函数（2 个少一个）、localStorage 泄漏（你的文件里出现 `localStorage` 直接红）三类全绿。

**闸门三 浏览器**：页面 0 控制台报错；发布后刷新，新活动仍在、草稿已清空。

- **L1 上一棒超时未交付**：老师已在 main 打 `wip/a4` 标签（半成品合入，允许 TODO，闸门必须绿）→ 照常从 main 拉，交接单写 `INHERITED: A4 未完成项 = <逐条列出>`。详情页没接完不影响发布页；你发布后跳 `#/detail/:id` 若渲染是桩，就在交接单记一条，用自己的"发布成功"提示兜住。
- **L2 上一棒提交的代码闸门红**：老师把 main 回退到 `seam/a5-start` 快照（= 开工前的纯定桩状态）→ 你**从定桩开工**，上游模块保持桩状态（`[SEAM 未实现]` 是合法的），你的模块照做，不受影响。"发现列表条数＋1"这条验收在 M2 还是桩时无法验证——按 `store.load().activities.length` 直接断言，写进交接单说明验证口径。
- **L3 上一棒彻底没来**：main 就是纯定桩 → 你照常开工，同上。

**关键认知：因为出题方预置了定桩，你的开工永远不被上游卡住。** 上游是桩、你的下游也是桩，接口在、签名在，你能跑自己的测试。你唯一不能被豁免的是自己模块的交付。
